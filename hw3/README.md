# HW3. Семантические проверки и типы Funny

Проверка имён и типов поверх парсера HW2: текст → AST (HW2) → таблицы символов, проверка типов и вывод типов
локальных переменных (бонус) → аннотированный AST (тип у каждого выражения) + список ошибок с позициями.
Правила типов и ограничения — [REPORT.md](REPORT.md).

## Требования

Python ≥ 3.12, только стандартная библиотека. Используются лексер, парсер и AST из `../hw2/funny`
(каталог добавляется в `sys.path` в `sema/__init__.py`), а через них — таблица лексера `../hw1/out/dfa.json`.

## Запуск

Команды выполняются из каталога `hw3/`.

```sh
python -m sema check program.funny          # аннотированный AST в stdout или ошибки в stderr
python -m sema check program.funny --json   # аннотированный AST в JSON
python -m sema check -                      # программа из stdin
python -m sema test                         # прогнать все тесты из tests/
```

```
$ python -m sema check tests/examples/step06_good_arrays_read_copy.funny

      VarDef a int[] @1:6

      Assign b @3:5

tests/err/inference.funny:9:5: cannot assign int[] to 'k': its type int was inferred at 8:9

```

Если программа не разбирается, печатаются синтаксические ошибки HW2 и проверка не запускается. Если разбирается,
но есть семантические ошибки, печатаются все они, а AST — нет. AST с типами печатается только для корректной программы.
Коды возврата: `0` — ошибок нет, `1` — ошибки в программе или упавшие тесты, `2` — ошибка ввода-вывода.

## Поддерживаемые конструкции

Весь язык, который разбирает HW2 (`grammar.ebnf` в `../hw2`): функции с `requires`/`returns`/`ensures`/`uses`,
формулы, все операторы (`=`, `a[i] = v`, `x, y = f(...)`, `if`/`else`, `while` с `invariant`, блоки, `assert`,
`assume`), все выражения, условия и предикаты (кванторы, ссылки на формулы, `length`).
Типы: `int`, `int[]`, `bool` (только условия и предикаты), кортеж типов (вызов функции с несколькими возвратами,
только в `x, y = f(...)`). Перегрузок и приведений типов нет.

## Таблицы символов и проверки имён

- **Модуль**: функции и формулы в одном пространстве имён; собираются первым проходом, поэтому вызовы вперёд
  и рекурсия работают. Повторное определение — ошибка.
- **Функция**: одна область — параметры, возвраты, локальные (`uses` и неявные, см. ниже). Блоки областей
  не создают (в Funny в блоке нельзя объявить переменную). Повторное имя — ошибка со ссылкой на первое объявление.
- **Кванторы**: переменная квантора кладётся на стек поверх области функции на время тела. Совпадение с видимым
  именем (другая переменная квантора, а также переменные, видимые в этом предикате) — ошибка.
- **Видимость по месту** (`funny.ru.md`): `requires` — только параметры, `ensures` — параметры и возвраты,
  тело/`invariant`/`assert`/`assume` — всё, формула — свои параметры.
- **Порядок**: операторы проверяются в порядке текста. Неизвестное имя в левой части `x = ...` или `x, y = ...`
  объявляет новую локальную (так написаны примеры `project/examples`, см. отступления); чтение имени,
  которое к этому месту не объявлено, — «unknown variable» (использование до объявления).
- **Запись в параметр** (в том числе `a[i] = v` для параметра-массива) — ошибка.
- Переменные и функции — разные пространства имён (вызов синтаксически отличим): локальная `twice` не мешает
  функции `twice` (`tests/ok/names.funny`).

## Вывод типов локальных (бонус)

Локальная без типа (`uses t` или неявная) получает переменную типа. Проверка выражений — унификация: контекст
требует тип (`+` и сравнения — `int`, индексация — `int[]` и индекс `int`, аргумент — тип параметра, присваивание —
тип значения), неизвестный тип привязывается к требуемому, две неизвестных связываются (`t = u;`).
Поэтому тип задаёт первое присваивание (или использование), а противоречие с ним — ошибка с позицией, где тип
был выведен: `cannot assign int[] to 'tmp': its type int was inferred at 2:5`. Если к концу функции тип
неизвестен — `cannot infer the type of local 't'`. `a[i] = 42;` (= `a = set(a, i, 42)`) даёт `a: int[]`.

Ошибочное выражение получает тип `?`, который совместим со всем: одна ошибка — одно сообщение. Если локальной
присвоено ошибочное значение, «cannot infer» для неё не сообщается (`no_cascade` в `tests/err/inference.funny`).

## Диагностика

Формат как в HW2: `файл:строка:столбец: сообщение`, позиция — узла AST (имени, оператора, первой цели
присваивания). Сообщение называет место, ожидаемый и фактический тип: `the index of 'b' must be int, got int[]`,
`argument 1 of 'g' (x) must be int, got int[]`, `'f' returns 2 values, but 3 variables are assigned`.
Проверка не останавливается на ошибке: все ошибки всех определений, отсортированные по позиции.

## Формат аннотированного AST (для HW4)

Узлы и поля — как в HW2 (таблица в `../hw2/README.md`), плюс:

- у каждого выражения поле `type`: `"int"`, `"int[]"`, `"bool"`, у `Call` в `MultiAssign` — список типов
  возвратов (`["int", "int"]`);
- у локальных без аннотации `VarDef.type` заполнен выведенным типом;
- неявно объявленные локальные дописаны в `Function.uses` (в порядке первого присваивания, позиция — его),
  так что `params` + `returns` + `uses` — полный список переменных функции с типами.

В текстовом дампе тип пишется в конце строки выражения: `Binary + @2:11 : int`; в JSON — поле `"type"`.

## Тесты

`python -m sema test` проверяет каждый `tests/**/ИМЯ.funny` и сравнивает с `ИМЯ.typed` (эталонный аннотированный
AST, если ошибок нет) или `ИМЯ.err` (эталонные ошибки, синтаксические или семантические, без имени файла).

| Каталог | Что |
|---|---|
| `tests/ok/` | `names` — вызовы вперёд, рекурсия, формулы, кванторы, видимость, одноимённые локальная и функция; `types` — все виды выражений и операторов, кортежи, массивы и обновления, вызовы в предикатах; `inference` — вывод из присваивания, копии массива, кортежа, `a[0] = 42`, связывание `t = u` |
| `tests/err/` | `names` — повторные определения/объявления, видимость в `requires`/`ensures`, использование до объявления, неизвестные переменная/функция/формула, конфликт переменных кванторов; `types` — `int`/`int[]` в арифметике, индексах, сравнениях, `length`, число и типы аргументов, многозначный вызов в выражении, неверная длина кортежа, формула вместо функции и наоборот, запись в параметр, несовместимое присваивание; `inference` — противоречие с присваиванием и с использованием, невыводимый тип, отсутствие каскада |
| `tests/examples/` | все 42 программы из `project/examples` (`шаг_имя.funny`): каждый `bad_*` даёт ожидаемую ошибку, `good_*` — AST с типами (кроме двух из таблицы отступлений) |

Эталоны записаны по выводу программы и проверены вручную. Что тесты ловят поломки, проверено порчей чекера:
без запрета записи в параметры падают 5 тестов, если унификация всегда успешна — 4, без правил видимости
в `requires`/`ensures` — 2, без ошибки «cannot infer» — 1.
