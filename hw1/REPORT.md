# Отчёт по HW1: регулярные выражения → ДКА → минимизация

## 1. Регулярные выражения токенов

Полная спецификация — [tokens.spec](tokens.spec). Если строка принимается несколькими правилами, выигрывает
записанное раньше.

| Токен | Регулярное выражение |
|---|---|
| `KW_FUNCTION` … `KW_LENGTH` (20 шт.) | `function`, `requires`, `returns`, `ensures`, `uses`, `int`, `if`, `else`, `while`, `invariant`, `assert`, `assume`, `true`, `false`, `not`, `and`, `or`, `forall`, `exists`, `length` |
| `IDENT` | `[A-Za-z_][A-Za-z0-9_]*` |
| `INT` | `0\|[1-9][0-9]*` |
| `BAD_NUMBER` (error) | `0[0-9]+\|[0-9]+[A-Za-z_][A-Za-z0-9_]*` |
| `ARROW` `IMPLIES` `EQ` `NE` `LE` `GE` | `->` `=>` `==` `!=` `<=` `>=` |
| `LT` `GT` `ASSIGN` `PLUS` `MINUS` `STAR` `SLASH` | `<` `>` `=` `\+` `-` `\*` `/` |
| `COMMA` `SEMI` `COLON` `PIPE` | `,` `;` `:` `\|` |
| `LPAREN` `RPAREN` `LBRACKET` `RBRACKET` `LBRACE` `RBRACE` | `\(` `\)` `\[` `\]` `{` `}` |
| `WS` (skip) | `[ \t\r\n]+` |
| `COMMENT` (skip) | `//[^\n]*` |

Ключевые слова стоят раньше `IDENT`. Кроме списка из условия добавлены лексемы грамматики Funny:
`requires`, `ensures`, `int`, `forall`, `exists`, `->`, `=>`, `:`, `|`.

**Числа с ведущим нулём.** `INT` не допускает ведущих нулей. Но при разбиении на токены по longest match строка
`01` иначе разобралась бы как `INT INT`. Поэтому добавлен токен-ошибка `BAD_NUMBER` (флаг `error`): он длиннее и
выигрывает, и лексер сообщает об ошибке. Так же обрабатываются цифры, слитые с буквами (`1abc`, `0x1F`).

## 2. Построение

1. Разбор регулярного выражения (`regex.py`) в AST: `Chars`, `Concat`, `Alt`, `Star`, `Epsilon`; `a+` = `a a*`.
2. Томпсон (`nfa.py`): общее начальное состояние с ε-переходами во фрагмент каждого правила; конечное состояние
   фрагмента помечено номером правила.
3. Построение подмножеств (`dfa.py`). Если в подмножестве несколько принимающих состояний, выигрывает правило
   с меньшим номером: `if` → `KW_IF`, а не `IDENT`.
4. Минимизация Хопкрофта. Начальное разбиение — по принимаемому токену, а не только «принимает / не принимает»,
   иначе склеились бы состояния после `if` (`KW_IF`) и после `ix` (`IDENT`).

## 3. Размеры автомата

| Этап | Состояний |
|---|---|
| НКА Томпсона (48 правил) | 319 |
| ДКА после построения подмножеств | 130 (включая ловушку) |
| Минимальный ДКА | **123** (включая ловушку) |

Минимизация склеила 7 состояний: «после первого символа» и «внутри цикла» у правил вида `x+` и `x y*`, а у
`BAD_NUMBER` — хвосты двух альтернатив, которые сходятся в один `[A-Za-z0-9_]*`.

| Токен | Склеены состояния после |
|---|---|
| `WS` | `\t` и `\t\t` |
| `INT` | `1` и `10` |
| `IDENT` | `A` и `A0` |
| `COMMENT` | `//` и `//x` |
| `BAD_NUMBER` | `00`, `0A`, `000`, `0A0` |

## 4. Ловушка

- ДКА полный: из каждого состояния есть переход по каждому символу алфавита. Все переходы, не ведущие ни к одному
  токену, идут в одно состояние-ловушку (`"trap": 1`), которое ничего не принимает и из которого нет выхода.
- Алфавит: 128 кодов ASCII и служебный символ «любой не-ASCII» (столбец 128).
- Не-ASCII символ (`é`, `ж`) и ASCII-символы, с которых не начинается ни один токен (`@`, `#`, `$`, DEL), ведут
  в ловушку.
- Исключение — тело комментария: `[^\n]` включает и не-ASCII символ, поэтому `// комментарий` допустим.
  Иначе лексер не разобрал бы примеры проекта, где все комментарии на русском. Вне комментария не-ASCII
  по-прежнему ведёт в ловушку.

## 5. Тестирование

`tests/cases.tsv` — 188 тестов, каждый прогоняется на минимальном и на исходном ДКА.

**135 тестов `match`** — строка целиком через ДКА, ожидается токен, `TRAP` или `REJECT`: пустая строка; только
пробелы, табы, CRLF; `0`, `00`, `01`, `007` (`BAD_NUMBER`); идентификаторы с `_`; все ключевые слова, их префиксы и продолжения
(`iff`, `If`, `_if`); все операторы и разделители; комментарии; не-ASCII (ловушка). Каждый из 128 ASCII-кодов
встречается в тестах: буквы и цифры — в токенах, 43 кода, с которых не начинается ни один токен, — отдельными
тестами `TRAP`.

**53 теста `lex`** — строка разбивается на токены по longest match, `WS` и `COMMENT` отбрасываются:
- 35 строк, которые разбираются целиком: короткие выражения, ключевые слова на границах (`ifx if iff`, `if(x)`),
  неоднозначные операторы (`a===b` → `EQ ASSIGN`, `a<==b`, `a->b=>c`), комментарии с CRLF и кириллицей и программы
  из `project/examples` (шаги 01, 07, 09, 10, 11, 12, 13, 14);
- 18 строк с ошибкой: числа с ведущим нулём и слитые с буквами (`x = 01;`, `a[1abc]`) и символы, с которых
  не начинается ни один токен: `@`, одиночный `!`, `"`, `.`, `#`, `&`, `?`, `$`,
  `%`, вертикальная табуляция, не-ASCII вне комментария и Unicode-стрелка `→` из примера
  `step12/good_formulas_sorted` (по грамматике импликация пишется `->`). Ожидается смещение места ошибки.

Ожидаемые токены записаны вручную. Если поставить `IDENT` выше ключевых слов, падают 32 теста.
