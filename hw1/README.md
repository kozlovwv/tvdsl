# HW1. Лексер Funny: регулярное выражение → НКА → ДКА → минимальный ДКА

Без библиотек регулярных выражений: разбор регулярных выражений, построение Томпсона, построение подмножеств,
минимизация Хопкрофта, ловушка, экспорт таблицы переходов в JSON и разбиение текста на токены по этой таблице
(longest match). Отчёт — в [REPORT.md](REPORT.md).

## Требования

Python ≥ 3.12, только стандартная библиотека.

## Запуск

Команды выполняются из каталога `hw1/`.

```sh
python -m lexgen build --json out/dfa.json   # построить автомат, вывести размеры, сохранить таблицу
python -m lexgen test                        # прогнать tests/cases.tsv, статус каждого теста
```

```
$ python -m lexgen build --json out/dfa.json
rules:            47
NFA states:       297
DFA states:       126 (incl. trap)
min DFA states:   122 (incl. trap)
table written to  out/dfa.json
```

Коды возврата: `0` — успех, `1` — есть упавшие тесты, `2` — ошибка в спецификации или аргументах.

## Структура

| Файл | Содержимое |
|---|---|
| `tokens.spec` | Регулярные выражения токенов Funny (порядок = приоритет) |
| `lexgen/spec.py` | Чтение `tokens.spec` |
| `lexgen/regex.py` | Разбор регулярного выражения рекурсивным спуском в AST |
| `lexgen/nfa.py` | Построение Томпсона: AST → ε-НКА |
| `lexgen/dfa.py` | Построение подмножеств и минимизация Хопкрофта |
| `lexgen/build.py` | Весь конвейер: spec → НКА → ДКА → минимальный ДКА |
| `lexgen/table.py` | Таблица переходов и её сохранение в JSON |
| `lexgen/lexer.py` | Прогон текста по таблице: строка целиком как один токен; разбиение на токены |
| `lexgen/cases.py` | Формат файла тестов и их прогон |
| `lexgen/__main__.py` | CLI |
| `tests/cases.tsv` | Тестовые строки и ожидаемые результаты |
| `out/dfa.json` | Экспортированный минимальный ДКА |

## Формат спецификации токенов

```
NAME [skip] = regex
```

Регулярное выражение — остаток строки после первого `=`. Если строка принимается несколькими правилами, выигрывает
записанное раньше, поэтому ключевые слова стоят перед `IDENT`. `skip` помечает токены, которые лексер не выдаёт
(пробелы, комментарии).

Синтаксис: литералы, `\n \t \r`, экранирование метасимволов, классы `[a-z]` и `[^\n]`, группы, `|`, `*`, `+`.

## Формат таблицы (`out/dfa.json`)

```
{
  "format": "funny-lexer-dfa/1",
  "start": 0,                   // начальное состояние
  "trap": 1,                    // ловушка: из неё нет выхода, токен не принимается
  "skip": ["COMMENT", "WS"],    // токены, которые лексер пропускает
  "accept": [...],              // для каждого состояния: имя принимаемого токена или null
  "transitions": [[...], ...]   // transitions[состояние][символ] → состояние, 129 столбцов
}
```

Столбец `c` — символ с ASCII-кодом `c`, столбец `128` — любой не-ASCII символ: переход по `ch` —
`transitions[state][min(ord(ch), 128)]`. Таблица полная: из каждого состояния есть переход по каждому столбцу.

## Формат тестов (`tests/cases.tsv`)

```
kind <TAB> input <TAB> expected [<TAB> комментарий]
match  01        TRAP                     строка целиком → токен | TRAP | REJECT
lex    x = 1;    IDENT ASSIGN INT SEMI    строка, разбитая на токены, или ERROR <смещение>
```

- `match` — строка целиком прогоняется через ДКА. `TRAP` — автомат попал в ловушку (ни один токен так не
  начинается), `REJECT` — строка является незаконченным началом токена (пустая строка, одиночный `!`).
- `lex` — строка режется на токены: от текущей позиции автомат идёт до ловушки, берётся самый длинный принятый
  префикс, `WS` и `COMMENT` (skip) отбрасываются. Если с текущего символа не начинается ни один токен —
  `ERROR n`, где `n` — смещение этого символа от начала строки (с нуля). Пустое ожидание — ни одного токена.

Во входной строке используются экранирования Python (`\n`, `\t`, `\r`, `\u00e9`, `\x23`), сам файл — чистый ASCII;
строки, начинающиеся с `#`, — комментарии.

`python -m lexgen test` прогоняет каждый тест и на минимальном, и на исходном ДКА: оба обязаны дать ожидаемый результат.
