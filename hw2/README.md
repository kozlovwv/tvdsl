# HW2. Парсер Funny: LL(1), рекурсивный спуск

Синтаксический анализатор Funny: лексер по таблице из HW1 → LL(1)-парсер рекурсивным спуском → AST
(текст или JSON) и диагностика ошибок с позициями. Восстановление после ошибок — режим паники.
Финальная грамматика — [grammar.ebnf](grammar.ebnf).

## Требования

Python ≥ 3.12, только стандартная библиотека. Лексер читает таблицу, экспортированную HW1:
`../hw1/out/dfa.json` (собирается командой `python -m lexgen build --json out/dfa.json` в `hw1/`; файл уже лежит
в репозитории).

## Запуск

Команды выполняются из каталога `hw2/`.

```sh
python -m funny parse program.funny          # AST в текстовом виде (или ошибки в stderr)
python -m funny parse program.funny --json   # AST в JSON
python -m funny parse -                      # программа из stdin
python -m funny test                         # прогнать все тесты из tests/
python -m funny --table путь/dfa.json ...    # другая таблица лексера
```

```
$ python -m funny parse tests/examples/step01_good_basic.funny
Program
  Function main @1:1
    returns:
      VarDef r int @1:16
    body: Block @1:22
      Assign r @2:5
        value: Binary + @2:11
          Num 1 @2:9
          Binary * @2:15
            Num 2 @2:13
            Num 3 @2:17

$ python -m funny parse tests/examples/step04_bad_missing_paren.funny
tests/examples/step04_bad_missing_paren.funny:2:15: expected ')' after the condition of 'if', got '{'
```

Коды возврата: `0` — успех, `1` — ошибки в программе или упавшие тесты, `2` — ошибка ввода-вывода или таблицы.

## Структура

| Файл | Содержимое |

| `funny/parser.py` | Рекурсивный спуск, проверка сортов, режим паники |
| `funny/ast.py` | Узлы AST, вывод в JSON и текстовый дамп |

## Лексер (интеграция с HW1)

`funny/lexer.py` загружает таблицу переходов минимального ДКА из `hw1/out/dfa.json` и режет текст на токены
по longest match: от текущей позиции автомат идёт до ловушки, берётся самый длинный принятый префикс. Приоритет
правил (ключевые слова раньше `IDENT`) уже учтён в таблице. `WS` и `COMMENT` (поле `skip`) отбрасываются,
`BAD_NUMBER` (поле `errors`: `01`, `1abc`) — лексическая ошибка. Каждый токен — `Token(kind, text, pos)`,
`pos` — строка и столбец с 1, табуляция — один столбец, CRLF — перевод строки. В конце потока — токен `EOF`.

После лексической ошибки лексер пропускает плохой символ (или весь `BAD_NUMBER`) и продолжает, поэтому сообщаются
все лексические ошибки сразу. Если они есть, разбор не запускается.

## Грамматика и LL(1)

Полностью — [grammar.ebnf](grammar.ebnf). Преобразования грамматики `funny.ru.md`:

1. **Левая рекурсия** `expr = expr "+" expr | ...` заменена уровнями приоритета с повторением:
   `sum = product { ("+" | "-") product }`. Цикл строит дерево слева направо, поэтому левая ассоциативность
   сохраняется: `a - b - c` = `(a - b) - c`.
2. **Факторизация общих префиксов:**
   - функция и формула начинаются одинаково (`имя ( параметры )`), выбор делается по следующему токену:
     `=>` — формула, `requires`/`returns` — функция;
   - три формы присваивания начинаются с `IDENT`; форма выбирается по токену после имени: `=` (`x = e;`),
     `[` (`a[i] = e;`), `,` (`x, y = f(...);`);
   - `IDENT` в выражении: `(` — вызов, `[` — элемент массива, иначе переменная.
3. **Выражения, условия и предикаты — одна грамматика.** В `funny.ru.md` это три разных нетерминала, и они
   не LL(k) ни при каком k: в условии `(` может открывать и `(a + b) < c` (выражение), и `(a < b) and c` (условие),
   а закрывающая `)` сколь угодно далеко. То же с `f(x)`: вызов функции или ссылка на формулу. Поэтому парсер
   разбирает их общей LL(1)-грамматикой, а каждому узлу даёт **сорт**: `num` (число) или `bool` (истинностное
   значение). Каждый оператор проверяет сорта операндов сразу после построения узла, ошибка сообщается с позицией.
   Вызов `f(...)` получает сорт по месту: где нужно число — `Call`, где нужно условие — `FormulaRef`.
   Итог совпадает с языком трёх грамматик `funny.ru.md` (с учётом отступлений ниже).

Приоритеты, от слабого к сильному:

| Операторы | Ассоциативность | Нетерминал |
|---|---|---|
| `->` | правая | `implies` |
| `or` | левая | `orExpr` |
| `and` | левая | `andExpr` |
| `not` | префиксный | `notExpr` |
| `== != < <= > >=` | нет (`a < b < c` — ошибка) | `comparison` |
| `+ -` | левая | `sum` |
| `* /` | левая | `product` |
| `-` (унарный) | префиксный | `unary` |

**LL(1)-проверка.** В каждой точке выбора альтернативы различаются первым токеном (множества FIRST указаны
в `grammar.ebnf`), а у необязательных частей `[ ... ]` и повторений `{ ... }` первый токен не входит в FOLLOW —
например, `->` и операторы сравнения не могут стоять после условия, `;` — после формулы, `:` — после
локальной переменной в `uses`. Единственный конфликт — **dangling else**: в `if (a) if (b) s1; else s2;` токен
`else` есть и в FIRST необязательной ветки, и в FOLLOW внутреннего `if`. Он разрешён стандартно: `else` относится
к ближайшему `if` (парсер забирает `else`, как только его видит).

## Обработка ошибок

Формат: `файл:строка:столбец: сообщение`. Сообщение называет ожидаемое и найденное:
`expected ')' to close '(' at 2:9, got ';'`, `the condition of 'if' must be a logical expression, got a number
expression`, `missing '}' to close the block opened at 1:22`.

**Режим паники.** Синтаксическая ошибка прерывает разбор текущей конструкции, ошибка записывается, токены
пропускаются до синхронизирующего, и разбор продолжается:

| Где поймана | Синхронизирующие токены |
|---|---|
| оператор внутри блока | `;` (поглощается), `}`, начало оператора (`{ if while assert assume`), конец файла |
| функция или формула | до конца текущего определения (с учётом вложенных `{ }`), до следующего имени после `}` или `;` |

Каждая ошибка сообщается один раз, каскада ложных ошибок нет (см. `tests/err/recovery.funny`: 6 ошибок в трёх
функциях — 6 сообщений). **Зацикливания нет:** каждый пропуск либо съедает хотя бы один токен, либо
останавливается на токене, который следующий шаг разбора гарантированно съест (`}` закрывает блок, ключевое слово
начинает оператор); ошибка же возможна только на токене, которым оператор начаться не может.

## Формат AST (API для следующих работ)

Узлы — dataclass'ы в `funny/ast.py`. У каждого узла есть `pos` — позиция токена, который «называет» узел: оператора
у `Binary`/`Unary`, имени у `Var`/`Call`/`Function`, ключевого слова у `If`/`While`/`Assert`, `{` у `Block`, первой
цели у присваивания.

| Узел | Поля |
|---|---|
| `Program` | `items: [Function \| Formula]` в порядке файла |
| `Function` | `name, params: [VarDef], requires: Expr?, returns: [VarDef], ensures: Expr?, uses: [VarDef], body: Stmt` |
| `Formula` | `name, params: [VarDef], body: Expr` |
| `VarDef` | `name, type` — `"int"`, `"int[]"` или `null` (локальная в `uses` без типа) |
| `Block` | `stmts: [Stmt]` |
| `Assign` | `target, value: Expr` |
| `MultiAssign` | `targets: [str], call: Call` |
| `If` | `cond, then: Stmt, else: Stmt?` |
| `While` | `cond, invariant: Expr?, body: Stmt` |
| `Assert`, `Assume` | `pred` |
| `Num`, `BoolLit` | `value` |
| `Var` | `name` |
| `Index` | `array: str, index: Expr` — `a[i]` |
| `Call` | `name, args` — вызов функции, в том числе `length(a)` |
| `FormulaRef` | `name, args` — `f(...)` там, где нужно условие (только в предикатах) |
| `Unary` | `op: "-" \| "not", operand` |
| `Binary` | `op: + - * / == != < <= > >= and or ->, left, right` |
| `Quantifier` | `kind: "forall" \| "exists", var: VarDef, body` |
| `Update` | `array, index, value` — функциональное обновление (копия массива с заменённым элементом) |

`?` — поле может быть `null`: `requires`/`ensures`/`invariant` не записаны (по `funny.ru.md` они по умолчанию
`true`/`false`/`true`; подстановку умолчаний оставляем следующим этапам).

**Обессахаривание.** `a[i] = v;` разбирается сразу в `Assign(a, Update(Var a, i, v))`, то есть `a = set(a, i, v)`
из `funny.ru.md`. Отдельного узла «присваивание элементу» нет.

**JSON** (`--json`): каждый узел — объект с полем `"node"` (имя класса), полями узла и
`"pos": {"line": 2, "col": 11}`; `else_` записывается как `"else"`.

**Текстовый дамп** (по умолчанию и в эталонах тестов): узел на строку, дети с отступом, скалярные поля в строке
узла, дочерние поля подписаны (`cond:`, `then:`), пустые поля не выводятся:

```
If @3:5
  cond: Binary > @3:11
    Var x @3:9
    Var y @3:13
  then: Assign r @3:16
    value: Var x @3:20
```

## Отступления от грамматики

| Отступление | Источник | Решение |
|---|---|---|
| Необязательное `function` перед определением | P02/P03: `function f(x:int) returns r:int {...}`; в `funny.ru.md` и `project/examples` его нет | принимаются обе записи; `function` зарезервировано (HW1) |
| `;` после формулы | `project/examples/step12`: `... => forall (...);`, в грамматике `;` нет | `;` необязательна |
| `->` в предикатах | в `funny.ru.md` импликация есть только в `condition`, но `step12` использует её в формуле | `->` разрешена в условиях и предикатах |
| Unicode-стрелка `→` | текст `funny.ru.md` и `step12/good_formulas_sorted`; грамматика — `"->"`, алфавит ASCII (HW1) | не поддерживается: лексическая ошибка (тест `examples/step12_good_formulas_sorted`) |
| Унарный минус | `"-" expr` без приоритета | связывает сильнее `*`: `-a * b` = `(-a) * b` |
| Сравнения без цепочек | в грамматике `comparison = expr op expr` | `a < b < c` — ошибка с подсказкой |
| `length` | встроенная функция, но в HW1 — ключевое слово | разбирается как `Call("length", args)` |
| `_` в идентификаторах | `funny.ru.md`: буквы и цифры; HW1/P01: и `_` | разрешён (как в HW1) |
| `a[i][j] = v` | упомянуто в `funny.ru.md`, но массивы одномерные, `arrayAccess = varName "[" expr "]"` | не поддерживается: синтаксическая ошибка |

Проверки имён и типов (необъявленная переменная, число аргументов, запись в параметр) — не синтаксис; это T1.
Поэтому `bad_*`-примеры с такими ошибками разбираются без ошибок. Исключение — `bad_int_condition` (`if (r)`) и
`bad_assert_nonpredicate` (`assert r;`): по грамматике число не может быть условием, это ловит проверка сортов.

## Тесты

`python -m funny test` разбирает каждый `tests/**/ИМЯ.funny` и сравнивает результат с `ИМЯ.ast` (эталонный дамп
AST) или `ИМЯ.err` (эталонные сообщения об ошибках, без имени файла). Печатается PASS/FAIL по каждому файлу.

| Каталог | Что |
|---|---|
| `tests/ok/` | 9 программ по темам: приоритеты и ассоциативность, условия, dangling else, массивы и обессахаривание, кортежное присваивание, контракты/кванторы/формулы, операторы и блоки, `function`, позиции (табы, CRLF) |
| `tests/err/` | 19 программ с ошибками: пустой ввод и только комментарий, незакрытые `(` `{` и вызов, лишние токены и лишняя `}`, неверные операторы (`===`, `:=`, `<>`, `+*`, `=` в условии), цепочка сравнений, ошибки сортов, кванторы и формулы вне предикатов, кортеж без вызова, `a[i][j]`, ошибки заголовков, ошибки операторов, присваивание на верхнем уровне, восстановление после нескольких ошибок, лексические ошибки (`01`, `1abc`, `@`, `"`, не-ASCII) |
| `tests/examples/` | все 42 программы из `project/examples` (`шаг_имя.funny`): хорошие и семантически плохие дают AST, синтаксически плохие — ошибку |

Эталоны `.ast` и `.err` записаны по выводу парсера; все `.err` и деревья для приоритетов, условий, dangling else,
обессахаривания, контрактов и позиций проверены вручную. Что тесты действительно что-то проверяют,
проверено порчей парсера: если поставить `+` и `*` на один уровень, падают 3 теста; если отключить проверку сортов —
7; если привязать `else` к внешнему `if` — 5; если сделать `-` правоассоциативным — 2.
