# Отчёт по HW4: IR, оптимизации и раскраска

## Генерация и CFG

Из аннотированного AST HW3 строится типизированный трёхадресный код. Ветвление создаёт два
блока ветвей и общий выход, цикл — заголовок, тело и выход с обратным ребром в заголовок.
Блоки создаются при генерации, поэтому каждый переход является границей блока, скрытых
переходов нет. Поддерживаются выражения, вызовы, множественный возврат, массивы и функциональные
обновления. Формат обмена с генератором кода приведён в README.

## Оптимизации

| Проход | Реализация |
|---|---|
| Константы | Таблица известных значений внутри каждого блока; подстановка в операнды и свёртка операций над литералами; запись в переменную сбрасывает её прежнее значение |
| Алгебра | `x+0`, `0+x`, `x-0`, `x*1`, `1*x`, `x/1` → `x`; `x*0`, `0*x` → `0` |
| DCE | Обратный проход от OUT блока; удаление неиспользуемых результатов безопасных операций, повтор до устойчивого результата |

Таблица констант не переносится через границы блоков. DCE использует межблочную живость,
чтобы сохранить значения, нужные после ветвлений и на следующей итерации цикла.
Вызовы, деления, чтения и обновления массивов сохраняются даже при неиспользуемом результате:
они могут завершиться ошибкой. Свёртка деления на ноль не выполняется. Преобразование `x*0`
не удаляет предшествующий вызов или чтение массива, вычисляющие `x`.

Арифметика при свёртке и исполнении — знаковая int32 с переполнением по модулю 2^32,
деление округляется к нулю. Опциональный CSE не реализован.

## Живость и раскраска

Для каждого блока вычисляются USE и DEF. Итерации до неподвижной точки:

```
OUT[B] = union(IN[S] for S in successors(B))
IN[B]  = USE[B] union (OUT[B] - DEF[B])
```

Обратный проход по инструкциям строит рёбра между одновременно живыми значениями и между
записываемыми результатами и живыми значениями. Одновременные результаты вызова также конфликтуют.
Граф консервативный: объединение регистров для копий не выполняется. Жадная раскраска обходит
вершины по убыванию степени, при равенстве — по имени, и выбирает минимальный свободный цвет.

## Эффект

Для `tests/basic.funny`, `calc(x) = 20 + x`:

| Метрика | До | После |
|---|---:|---:|
| Инструкции, включая return | 10 | 4 |
| Встречающиеся временные | 5 | 2 |

Удалены вычисление `dead`, промежуточные константы и умножение на единицу. После оптимизации
достаточно одного цвета: значения последовательно занимают один абстрактный регистр.
Текстовые примеры до/после находятся в `tests/basic.before.ir` и `tests/basic.after.ir`.
Метрики остальных программ вычисляются при каждом `build`.

## Проверка и ограничения

Тесты сравнивают выполнение исходного и оптимизированного IR с ожидаемыми результатами,
проверяют сохранение исключений, CFG и раскраску. Интерпретатор нужен для тестирования IR;
он не является генератором JVM. За один запуск разрешено 100000 инструкций, включая рекурсивные
вызовы, чтобы ошибочный цикл не блокировал тесты. Чтение неинициализированных переменных остаётся
неопределённым поведением Funny. Логические аннотации сохраняются для верификации и не исполняются.
