# HW4. Промежуточное представление и базовые оптимизации Funny

Исходный текст → парсер HW2 → проверка имён и типов HW3 → трёхадресный IR и CFG → локальные
оптимизации → живость, граф конфликтов и жадная раскраска.

## Требования

Python ≥ 3.12, только стандартная библиотека. Используются `../hw3/sema`, `../hw2/funny`
и таблица лексера `../hw1/out/dfa.json`. Предыдущие работы не изменены.

## Запуск

Команды выполняются из каталога `hw4/`.

```sh
python -m ir build tests/basic.funny             # IR до/после, CFG, живость, граф, цвета, метрики
python -m ir build tests/control.funny --json    # тот же результат в JSON
python -m ir build -                            # программа из stdin
python -m ir build tests/basic.funny --no-opt    # отключить все оптимизации
python -m ir build tests/basic.funny --no-constants
python -m ir build tests/basic.funny --no-algebra
python -m ir build tests/basic.funny --no-dce
python -m ir test
```

По умолчанию включены все три оптимизации. Флаги `--no-constants`, `--no-algebra`, `--no-dce`
отключают их независимо. Ошибки HW2/HW3 выводятся как `файл:строка:столбец: сообщение`, IR при
ошибках не строится. Коды возврата: `0` — успех, `1` — ошибки программы/тестов, `2` — ошибка
ввода-вывода или неверный формат данных.

## Формат IR и API для генератора кода

`lower(program)` принимает проверенный и аннотированный объект `funny.ast.Program` из HW3.
Возвращает `(functions, formulas)`: список `ir.model.Function` и определения логических формул
в формате JSON AST HW3. Сериализация функций — `dataclasses.asdict`.

`Function` содержит `name`, списки имён `params` и `returns`, словарь `types` (имя → тип),
список `blocks` и логические `annotations`. В `types` входят исходные переменные и временные
`%1`, `%2`, … с типами `int`, `int[]`, `bool`. Имена временных не пересекаются с именами Funny.
После оптимизации таблица сохраняет также типы удалённых временных; метрики считают только
имена, встречающиеся в инструкциях.

`Block(label, code)` — базовый блок с уникальной в функции меткой `B0`, `B1`, … .
Первый блок — вход. Каждый блок заканчивается `jump`, `branch` или `return`.
Последовательность блоков не задаёт переходы: все рёбра CFG явные, в `target` последней инструкции.
`Block.successors()` возвращает эти метки.

`Instr(op, dest, args, target, name)`:

- `op` — операция;
- `dest` — список записываемых переменных;
- `args` — список операндов: строка означает переменную, целое/булево значение — литерал;
- `target` — список меток переходов;
- `name` — имя вызываемой функции (только `call`).

| Операция | `dest` | `args` | Семантика |
|---|---|---|---|
| `copy` | один результат | значение | присваивание, массив копируется |
| `+`, `-`, `*`, `/` | один результат | два `int` | арифметика int32, деление к нулю |
| `neg`, `not` | один результат | один операнд | унарная операция |
| `==`, `!=`, `<`, `<=`, `>`, `>=` | один результат | два `int` | сравнение |
| `and`, `or`, `->` | один результат | два `bool` | логические операции |
| `length` | один результат | массив | длина |
| `load` | один результат | массив, индекс | чтение с проверкой границ |
| `update` | один результат | массив, индекс, значение | копия массива с изменённым элементом |
| `call` | список результатов | аргументы | вызов `name`, включая рекурсию |
| `jump` | пусто | пусто | переход к `target[0]` |
| `branch` | пусто | условие | true → `target[0]`, false → `target[1]` |
| `return` | пусто | возвращаемые значения | выход из функции |

Аргументы и операнды вычисляются слева направо, логические операции вычисляют оба операнда.
Многозначный вызов сначала записывает результаты во временные, затем выполняет присваивания.
В конце функции создаётся `return` для переменных, объявленных в `returns`.

`requires`, `ensures`, `invariant`, `assert`, `assume` сохраняются как логические аннотации:
`kind`, `block`, позиция `source`, `predicate` (аннотированный JSON AST). Они не выполняются
интерпретатором и не участвуют в живости исполняемого кода. Для `assert` выбран разрешённый
спецификацией режим проверки при верификации. Аннотации относятся к исходной программе;
их позиции не являются индексами инструкций оптимизированного IR. Это также позволяет
сохранить кванторы и формулы без попытки перечислить все математические целые в рантайме.

`optimize(functions, constants=True, algebra=True, dce=True)` возвращает копию функций.
`allocate(function)` возвращает `live_in`, `live_out`, симметричный `graph`, словарь `colors`
и `color_count`. Конфликты считаются для исходных переменных и временных; цвета — номера
абстрактных регистров от нуля. Ограничение числа регистров и spill не реализуются.

Вывод `build --json`: `before`, `after`, `formulas`, `allocation`, `metrics`.
CFG уже содержится в `blocks`/`target`, граф конфликтов — в `allocation`.

## Тестирование

`python -m ir test` проверяет вычисления, вложенные ветвления и циклы, рекурсию, массивы,
множественные возвраты, переполнение int32, отрицательное деление, переопределения переменных,
ошибки деления/индексации и вызовы с ошибками. Для вычислительных примеров сравниваются результаты
до/после для всех восьми комбинаций флагов и с независимо заданными ожидаемыми значениями.

Отдельно проверяются рёбра CFG, живость на обратном ребре цикла, симметричность графа и разные
цвета у конфликтующих переменных. Все положительные примеры HW3 проходят генерацию IR,
оптимизацию и проверки графов. `basic.before.ir` и `basic.after.ir` — сохранённые примеры вывода,
проверяемые тестом. Эффект оптимизаций описан в [REPORT.md](REPORT.md).
